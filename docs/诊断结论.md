# 诊断结论与已知限制

## 启动拦截

YOYO Claw 的资源下载对话框检查了多个荣耀组件的包名和版本。测试时 `com.hihonor.pcengine` 的版本码 `100002233` 高于最低要求 `100002231`；`com.hihonor.pczone` 也通过检查。真正缺少的是 `com.hihonor.pcenginewps`，最低要求版本码为 `100003210`。荣耀应用市场详情入口在该设备上没有提供下载。

点击“立即下载”进入了荣耀 PC 应用专区，但没有生成该组件的下载任务。因此反复点击并不能完成安装。此现象是单台设备、当时市场环境的观察，其他地区和机型可能不同。

本次曾安装本地制作的无权限空包，仅让包名/版本检查通过。它没有 Activity、Service、Provider 或荣耀引擎代码。原版 YOYO 的主界面、普通对话和一次 shell 工具调用可用；与真实 PC 引擎耦合的功能没有验证。该实验不能证明所有功能已修复。仓库只为复核附上该诊断 APK，不应将其当作推荐安装包或适用于其他设备的通用方案；安装前请先阅读[包名冲突和回退说明](使用方法.md)。

## 模型调用

原版 YOYO 保存了火山引擎 Agent Plan 的 OpenAI 兼容配置（套餐专用 `/api/plan/v3` 地址与 `glm-5.3-flash`），完成了：

- 最小文字回复测试，收到预设校验字符串。
- shell 工具调用，执行 `printf` 固定字符串并把结果返回到对话。

这只证明当时的网络、套餐密钥、模型和应用配置可完成上述两类请求。不等于对所有工具、持续后台运行或 Bot 渠道完成兼容性认证。密钥未公开，也不应复制到公开 issue、截图或自动化脚本。

## “完全访问”菜单

前端在缩放聊天区域时没有同步处理 Portal 弹出菜单，导致菜单末尾选项被裁切。通过临时降低 Android density 可以显示该选项；恢复默认显示密度后，审批模式仍保留。根本的菜单布局问题仍需应用开发者修复，其他弹窗也可能存在类似裁切。

## Linux 实验室与 Kali

荣耀 Linux 实验室在应用私有目录中运行 `proot` 容器，并由荣耀组件管理。它不是普通的硬件虚拟机，也没有 Android root 或 `/dev/kvm`。Termux 的 `proot-distro` 文档明确说明不支持在另一个 proot 中嵌套运行，因此不建议在此容器内再套装 Kali，或替换现有 rootfs。

Android 侧独立安装 Kali NetHunter Rootless 是更现实的尝试：Kali 官方支持未 root 的 Android 设备使用 Kali CLI 和 KeX 桌面。但 Rootless 不会给 Android root 权限，也不提供需要专用内核的 Wi‑Fi 注入、HID 等能力。测试设备没有安装 Kali，MagicOS 上的稳定性和后台限制仍待实测。
